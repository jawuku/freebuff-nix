# freebuff-nix

Run the [`freebuff`](https://www.npmjs.com/package/freebuff) CLI inside an
FHS-compliant shell using Nix.

## Usage

Start a new session:

```sh
nix run .
```

This builds an FHS environment (`buildFHSEnvBubblewrap`) containing Node.js and
runs `npx freebuff`.

Resume a previous session by passing the session timestamp:

```sh
nix run . -- --continue 2026-08-01T15-51-31.852Z
```

Any arguments after `--` are forwarded to the `freebuff` CLI.

## Using this flake from a NixOS configuration

> **Note:** because this repo is a git repository, Nix only sees files that
> are tracked by git. After cloning or initialising the repo, commit the
> files (`git add . && git commit`) before the flake is usable.

Add it as an input to your NixOS flake, then either install the `freebuff`
command on the system or run it on demand.

### As a flake input

In your NixOS configuration's `flake.nix`:

```nix
{
  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";

    freebuff-nix = {
      url = "github:your-username/freebuff-nix";
      # Reuse your nixpkgs instead of fetching a second copy.
      inputs.nixpkgs.follows = "nixpkgs";
    };
  };

  outputs =
    { self, nixpkgs, freebuff-nix, ... }:
    {
      nixosConfigurations.myhost = nixpkgs.lib.nixosSystem {
        system = "x86_64-linux";
        modules = [
          ({ pkgs, ... }: {
            environment.systemPackages = [
              freebuff-nix.packages.${pkgs.system}.default
            ];
          })
        ];
      };
    };
}
```

If you haven't pushed this repo yet, use a local input instead of the GitHub
URL:

```nix
# Tracks committed state (only committed files are used):
url = "git+file:///home/jason/freebuff-nix";

# Or, for quick local iteration that reflects your live working tree
# (including uncommitted changes, no git required):
url = "path:/home/jason/freebuff-nix";
```

### Rebuild and run

```sh
sudo nixos-rebuild switch --flake /etc/nixos#myhost
```

The `freebuff` command is now on your system PATH. You can also run it on
demand without installing it, from anywhere inside your NixOS flake:

```sh
nix run freebuff-nix#                     # start a new session
nix run freebuff-nix# -- --continue 2026-08-01T15-51-31.852Z   # resume
```

Arguments after `--` are forwarded to the CLI, exactly like `nix run .` in
this repo.

## How it works

- [`flake.nix`](./flake.nix) defines a Nix **app** whose program is the wrapper
  generated by `buildFHSEnvBubblewrap`.
- The FHS environment provides a real `/usr`, `/lib`, `/etc`, etc., so npm
  packages that ship prebuilt native binaries (or hardcode FHS paths) work on
  NixOS and other Nix systems.
- `npx --yes freebuff` fetches and runs the latest `freebuff` from the npm
  registry, cached in `~/.npm/_npx` between runs, so startup stays fast after
  the first launch.

## Customizing

Add extra packages to the environment by editing `targetPkgs` in `flake.nix`,
for example `git`:

```nix
targetPkgs = p: with p; [
  nodejs
  cacert
  yarn
  git
];
```

## Binary cache (Cachix)

CI pushes build artifacts to a [Cachix](https://www.cachix.org/) cache named
`freebuff-nix`, so packages are built once and shared between CI runs and
local machines.

### CI setup

1. Create the cache: sign in at <https://app.cachix.org> and create a cache
   named `freebuff-nix`.
2. Add a Cachix **personal auth token** as the `CACHIX_AUTH_TOKEN` secret in
   your GitHub repository (Settings → Secrets and variables → Actions).
3. Done — the `flake-check` workflow pulls from (and, with the token, pushes
   to) the cache on every run. Fork PRs without the secret fall back to
   read-only pulling.

### Using the cache locally

To pull prebuilt packages from the cache on your machine:

```sh
nix run nixpkgs#cachix use freebuff-nix
```

Or declaratively on NixOS:

```nix
nix.settings = {
  substituters = [ "https://freebuff-nix.cachix.org" ];
  trusted-public-keys = [ "freebuff-nix.cachix.org-1:<PUBLIC KEY>" ];
};
```

`cachix use` configures the public key automatically; to get it manually, run
`cachix show-key` or view the cache page on Cachix.
